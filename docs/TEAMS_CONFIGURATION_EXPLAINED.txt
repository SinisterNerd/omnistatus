                 MICROSOFT TEAMS CONFIGURATION - EXPLAINED
================================================================================

WHAT YOU NEED TO CONFIGURE TEAMS:
──────────────────────────────────

    teams:
      enabled: true                    # Enable/disable Teams
      token: "YOUR_ACCESS_TOKEN"       # Microsoft Graph API token
      extra:
        user_id: "YOUR_USER_ID"        # Your Azure AD object ID


THE TWO CREDENTIALS EXPLAINED:
──────────────────────────────

    1. ACCESS TOKEN ("token" field)
       ├─ What it is: JWT-format API key
       ├─ What it proves: You have permission to use Microsoft Graph API
       ├─ What it does: Authenticates your API calls
       ├─ Where you get it: Azure Portal (OAuth 2.0 client credentials flow)
       ├─ Format: Starts with "eyJ0eXA..." (long string)
       ├─ Expiration: Expires after ~1 hour
       └─ Security: Treat like a password

    2. USER ID ("extra.user_id" field)
       ├─ What it is: UUID - your unique identifier in Azure AD
       ├─ What it does: Tells the API whose status to update
       ├─ Where you get it: Azure AD Users section
       ├─ Format: UUID like "12345678-1234-1234-1234-123456789012"
       └─ Never expires: Stay the same


WHY BOTH?
─────────

    Token = "Prove who you are"
      └─ Authorization header: Authorization: Bearer {token}

    User ID = "Update THIS person's status"
      └─ API endpoint: /v1.0/me/presence (the "me" is replaced with your ID)

    Without BOTH:
      Token without User ID   → API doesn't know whose status to update
      User ID without Token   → No permission to access Microsoft Graph API


WHAT GETS UPDATED:
──────────────────

    When you run: ost set --status "Meeting" --emoji ":calendar:" --state away

    Two API calls are made:

    1. Set Availability (presence indicator)
       ├─ Endpoint: POST /me/presence/setPresence
       ├─ Value: "Away" (maps from --state away)
       └─ Result: Yellow dot 🟡 appears next to your name in Teams

    2. Set Custom Status Message
       ├─ Endpoint: PATCH /me/presence
       ├─ Value: ":calendar: Meeting" (emoji + status)
       └─ Result: Text appears under your name in Team chat


STATE MAPPING:
──────────────

    Command line (--state)  →  Teams API       →  What others see
    
    active                  →  Available       →  🟢 Green dot
    away                    →  Away            →  🟡 Yellow dot
    dnd                     →  DoNotDisturb    →  🔴 Red dot


HOW TO GET THE CREDENTIALS - QUICK VERSION:
─────────────────────────────────────────────

    1. Go to Azure Portal (portal.azure.com)
    
    2. Register an App
       ├─ Azure Active Directory → App registrations → New registration
       ├─ Name: "omniStatus"
       └─ Click Register
    
    3. Add Permissions
       ├─ API permissions → Add a permission
       ├─ Select Microsoft Graph → Application permissions
       ├─ Add: Presence.ReadWrite
       ├─ Add: User.Read
       └─ Grant admin consent (button must be green)
    
    4. Create Client Secret
       ├─ Certificates & secrets → New client secret
       ├─ Expiration: 6 months
       ├─ Copy the secret VALUE (shown once!)
       └─ SAVE IT SECURELY TEMPORARILY
    
    5. Get Access Token
       curl -X POST "https://login.microsoftonline.com/YOUR_TENANT_ID/oauth2/v2.0/token" \
         -H "Content-Type: application/x-www-form-urlencoded" \
         -d "client_id=YOUR_CLIENT_ID" \
         -d "scope=https://graph.microsoft.com/.default" \
         -d "client_secret=YOUR_CLIENT_SECRET" \
         -d "grant_type=client_credentials"
       
       ├─ Response includes: "access_token": "eyJ0eXAi..."
       └─ Copy that token → goes in config.yaml

    6. Get User ID
       curl -X GET "https://graph.microsoft.com/v1.0/me" \
         -H "Authorization: Bearer YOUR_TOKEN"
       
       ├─ Response includes: "id": "12345-..."
       └─ Copy that ID → goes in config.yaml


CONFIGURATION FILE LOCATION:
────────────────────────────

    ~/.config/omnistatus/config.yaml

    Example:

    teams:
      enabled: true
      token: "eyJ0eXAiOiJKV1QiLCJhbGciOiJSUzI1NiIsIng1dCI6Imk2bEdrM0..."
      extra:
        user_id: "87654321-4321-4321-4321-210987654321"


USAGE EXAMPLES:
───────────────

    # Update availability and custom status
    ost set --status "In meeting" --emoji ":calendar:" --state away
    
    # Update with just status (default active)
    ost set --status "Coffee break" --emoji ":coffee:"
    
    # Clear status
    ost clear


CONCURRENCY:
────────────

    Teams update is concurrent with other platforms (Slack, Discord)
    
    ost set ... (launches all platforms at once)
    
    Timing:
    ├─ Slack:  ~300ms
    ├─ Teams:  ~400ms  
    └─ Discord: ~200ms
    
    Total: ~400ms (not 900ms) because they run in parallel!


ERROR HANDLING:
───────────────

    Token expired (>1 hour old)
    ├─ Error: Graph API returned status 401: Unauthorized
    ├─ Fix: Get new token using curl command above
    └─ Update: Paste new token in config.yaml

    Missing user_id
    ├─ Error: teams is not enabled or token/user_id is missing
    ├─ Check: user_id field is populated
    └─ Fix: Get your user_id and add to config

    Token invalid
    ├─ Error: Graph API returned status 401: Unauthorized
    ├─ Check: Token starts with "eyJ0eXA"
    └─ Verify: curl -X GET "https://graph.microsoft.com/v1.0/me" \
                       -H "Authorization: Bearer YOUR_TOKEN"


SECURITY NOTES:
───────────────

    ✓ Config file created with 0600 permissions (only you can read)
    ✓ Token never logged or printed
    ✓ Token only stored in config file
    ✓ Uses OAuth tokens (not passwords)
    ✓ Discord uses local socket (no cloud botting)

    ! Treat token like a password
    ! Never commit config.yaml to git
    ! Rotate credentials every 6-12 months
    ! Keep client secret safe until exchanged for token


SYNC TIMING:
────────────

    Availability (🟢🟡🔴): Instant
    Custom status message: 30-60 seconds
    All Teams clients: Auto-synced (desktop, web, mobile)


LIMITATIONS:
────────────

    • Maximum status message: 280 characters
    • Token expires: After ~1 hour
    • Can't use personal account: Use service account (recommended)
    • Status formatting: No markdown/rich text in Graph API


COMMON MISTAKES:
────────────────

    ❌ Using user_id without token
       → API says: "Not authorized"

    ❌ Using token without user_id
       → omniStatus says: "user_id is missing"

    ❌ Forgetting admin consent in Azure Portal
       → API won't return proper permissions error
       → Permission-denied later when trying to update

    ❌ YAML indentation wrong (tabs instead of spaces)
       → YAML parser fails silently or gives confusing error

    ❌ Token older than 1 hour
       → Get 401 Unauthorized error
       → Need to refresh token

    ❌ Confusing Client Secret with Access Token
       → Client Secret: Used to GET access token (one-time)
       → Access Token: Used to call Microsoft Graph (in config)


STEP-BY-STEP VALIDATION:
────────────────────────

    1. Is token valid?
       curl -X GET "https://graph.microsoft.com/v1.0/me" \
         -H "Authorization: Bearer YOUR_TOKEN"
       → Should return 200 OK with your user info

    2. Check what API has access to:
       curl -X GET "https://graph.microsoft.com/v1.0/me" \
         -H "Authorization: Bearer YOUR_TOKEN"
       → Look for "id" field (that's your user_id if you don't know it)

    3. Check current status:
       curl -X GET "https://graph.microsoft.com/v1.0/me/presence" \
         -H "Authorization: Bearer YOUR_TOKEN"
       → Should return your current availability and status message

    4. Test manual update:
       curl -X PATCH "https://graph.microsoft.com/v1.0/me/presence" \
         -H "Authorization: Bearer YOUR_TOKEN" \
         -H "Content-Type: application/json" \
         -d '{"statusMessage":{"content":"test"}}'
       → Should update your Teams status
